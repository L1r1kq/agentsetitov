# Изоляция — разбор для защиты

Полная таблица вариантов и связка: [REPORT.md §5](REPORT.md).

Выбранная связка:

1. **Контейнер приложения** — воспроизводимый Python/рантайм.
2. **Отдельный sandbox-контейнер** — exec с `cap_drop ALL`, `no-new-privileges`, `read_only`, `tmpfs /tmp`, `pids_limit`, `mem_limit`, сеть `internal` (без интернета).
3. **AST/denylist guard в приложении** — даже если HTTP sandbox мёртв.
4. **Не Docker socket** у app — иначе изоляция фикция.
5. **Не полная VM** как дефолт — дорого для eval-цикла на ноутбуке.
6. **gVisor/Firecracker/WASM** — следующий уровень на Linux-проде, не на M2-учёбе.

Готовая позиция: изолируем *опасную способность* (код), не весь чат.
