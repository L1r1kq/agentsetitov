--------------------------------------------------------------------------------
1. Краткое описание
--------------------------------------------------------------------------------

Agentse MedInfo — локальная мультиагентная система справочной разборки жалоб.
Пользователь описывает симптомы своими словами. Шесть ролей (supervisor, planner,
researcher, builder, critic, curator) структурируют жалобу, ищут карточки в
локальном справочнике workspace/knowledge/ и собирают справочный отчёт.

Система не ставит диагноз, не назначает лекарства и дозы, не заменяет врача.
При красных флагах (давящая боль в груди, одышка, кровь, потеря сознания)
первым блоком идёт срочная помощь 103 / 112.

Модель запускается локально через Ollama (дефолт gemma2:2b после бенча трёх
моделей). Оркестрация — LangGraph StateGraph. Есть CLI, веб-UI и REST API,
Docker Compose с песочницей, иерархическая память, evals и наблюдаемость.

Отличие от «чата с одной моделью»: явный граф, устав в markdown (SOUL / PURPOSE),
скиллы как файлы, детерминированный medical_guard и сборка отчёта из карточек
(маленькая 2B-модель не пишет клинику «из головы»).


--------------------------------------------------------------------------------
2. Задача и границы решения
--------------------------------------------------------------------------------

Задача проекта — дать человеку инструмент самопомощи до визита к врачу:
разобрать жалобу, сопоставить её со справочником и честно сказать, чего по
тексту решить нельзя. Это не телемедицина и не приём.

Вход: свободный текст на русском (симптомы, длительность, отрицания).
Выход: справочный отчёт с дисклеймером, структурой жалобы, смыслом карточки,
блоком красных флагов и следующим шагом без рецепта.

Границы v1:
  - нет интернета и живого поиска по PubMed;
  - нет постановки диагноза и подбора доз;
  - нет мультипользовательского SaaS и хранения медкарт;
  - инференс только локальный (Ollama);
  - исполнение кода только в песочнице (для расчётов, не для «лечения»).

Инференс выполняется на машине пользователя. Облачный OTEL/Langfuse по
умолчанию выключен (AGENTSE_OTEL_ENABLED=false), чтобы промпты и жалобы
не уезжали с ноутбука.


--------------------------------------------------------------------------------
3. Последовательность работы
--------------------------------------------------------------------------------

1) Методичка «LLM for Agent»: сравнить движки, прогнать лёгкие LLM, собрать агента.
2) Продуктовое назначение: MedInfo вместо «агента ради агента».
3) Архитектура: C4, Sequence, hybrid-маршрутизация.
4) Ядро: LangGraph, tools, HCM-память, soul/skills, medical_guard.
5) Изоляция: Docker Compose + sandbox + AST-guard.
6) Evals LLM (3 модели) и агентной системы, unit-тесты.
7) UI/API, починка пустого "{}" и дампа knowledge-файлов.
8) Наблюдаемость: Prometheus-метрики, JSON-логи, file traces, алерты.

Работа шла одним контуром: продукт + граф + память + evals + отчётность.


--------------------------------------------------------------------------------
4. Видение продукта и сценарий использования
--------------------------------------------------------------------------------

Ценность — локальная справка по жалобе без облачного врача и без диагноза.
Planner раскладывает текст на поля. Researcher ищет knowledge/. Builder
собирает человеческий отчёт из секции «Для человека». Critic и medical_guard
режут «у вас пневмония» и рецепты. Curator не кладёт симптомы в MEMORY.md.

Сценарий: человек пишет «температура 38.2 три дня и сухой кашель, одышки нет,
грудь не болит» → получает справку: ОРВИ-подобный паттерн в справочнике,
скорую не зовём по отрицаниям, к врачу если держится или станет хуже.

Tech/преподаватель видит маршрут ролей справа и может защитить решения
(Ollama, не RAG, Docker+sandbox, hybrid).


--------------------------------------------------------------------------------
5. Продуктовое описание по Working Backwards
--------------------------------------------------------------------------------

Agentse MedInfo помогает получить структурированную справку по симптомам без
ожидания приёма и без иллюзии диагноза. Он разбирает текст локальной моделью
и карточками, возвращает отчёт. Запуск — браузер http://127.0.0.1:8080/ или CLI.

Акцент: контроль среды, запрет диагноза на трёх уровнях (промпт, guard,
сборка отчёта), понятный дисклеймер. Время полного графа на M2/8ГБ — порядка
1–2 минут (несколько вызовов 2B-модели); тело справки собирается мгновенно.

11. Lean Canvas
--------------------------------------------------------------------------------

Потребность. Разобрать симптомы до врача без диагноза-галлюцинации и без
отправки жалобы в облако.

Решение. Шесть ролей LangGraph, локальная gemma2:2b, карточки knowledge/,
medical_guard, веб и CLI.

Ценность. Справочный отчёт в своей среде. Опорные свойства: локальность,
запрет диагноза, прозрачные soul/skills, evals.

Сегменты. Студенты LLM-курсов, люди с жалобами, преподаватели.

Каналы. Репозиторий, защита, README, демо UI.

Метрики. TSR агентного бенча, handoff accuracy, loop rate, доля отчётов
с дисклеймером, ложные диагнозы (должно быть 0 по guard).

Затраты. Разработка, 8 ГБ ноутбук, время прогона evals.

Доходы. v1 бесплатно.

16. Архитектура системы
--------------------------------------------------------------------------------

Пользователь → Web/CLI (FastAPI :8080) → Agent graph (LangGraph)
  → Ollama :11434 (gemma2:2b)
  → HierarchicalMemory (SQLite + markdown)
  → knowledge/*.md
  → sandbox :8090 (опционально)
  → /metrics (Prometheus)

Рисунок 1. Веб-интерфейс (вход жалобы).
файл: docs/report-assets/fig01-ui-medinfo.png

C4 Context (ASCII)

  [Оператор] --жалоба--> [Agentse MedInfo]
                              |--chat--> [Ollama]
                              |--exec--> [Sandbox]
                              |--metrics--> [Prom/Grafana/Alertmanager]
                              |--опц.--> [Langfuse / Tempo]

C4 Containers

  Web/CLI → Graph → Memory store → Tool runtime → Workspace markdown
                \-> Ollama
                \-> Docker sandbox

Граф выполнения (Sequence happy path)

  User -> Supervisor -> Planner -> Researcher -> Builder -> Critic
       -> Curator -> FINISH
  Researcher читает knowledge/
  Builder вызывает compose_reference_report (не свободный бред модели)
  Critic + medical_guard
  Curator не пишет PHI

  START → planner → researcher → builder → critic → curator → FINISH

Рисунок 2. Логический граф ролей (маршрут печатается в правом блоке UI).

Fan-out как у code-review (три параллельных ревьюера) здесь НЕ используется:
медсправка последовательна (сначала поля, потом карточки, потом текст,
потом санитар формулировок). Параллелить planner и researcher нельзя.

17. Состояние графа
--------------------------------------------------------------------------------

AgentState (упрощённо):

  task: str
  session_id: str
  plan: list[str]
  findings: list[str]
  artifacts: list[{artifact_type, content, notes}]
  critique: {verdict, issues, required_fix, score}
  next_agent: planner|researcher|builder|critic|curator|FINISH
  step: int
  route_trace: list[str]
  final_answer: str
  scores: dict

Hybrid merge_route: без плана нельзя уйти с planner; FINISH без критика
запрещён; повтор researcher режется политикой. Это якорь для 2B.

21. Память: почему не RAG
--------------------------------------------------------------------------------

Vanilla RAG (нарезка + top-k) отвергнут как единственный слой:
нет записи, нет времени, нет владельца факта, душа конкурирует с daily
notes, сходство ≠ уместность жалобы.

Смотрели: GraphRAG, HippoRAG/LightRAG, MemGPT/Letta, Mem0, Zep/Graphiti,
OpenClaw markdown.

Выбор: Hierarchical Cognitive Memory
  identity markdown (бутстрап с бюджетом)
  episodic SQLite FTS + memory/YYYY-MM-DD.md
  entity graph + decay
  curator после задачи
  knowledge/ как процедурный справочник (не ANN)

Для тела медсправки v1 ещё жёстче: select_cards по ключам темы
(температур/кашел → fever_cough.md), секция «Для человека».
INDEX.md в ответ человеку не попадает.

22. Изоляция
--------------------------------------------------------------------------------

Вариант                 Вердикт
----------------------  --------------------------------------------------------
venv / процесс          недостаточно
Контейнер app           да, control plane

                        tmpfs, pids/mem, сеть internal

29. Выводы
--------------------------------------------------------------------------------

Продуктовый сценарий связан с техникой: жалоба идёт в UI/CLI, шесть ролей
LangGraph делают конвейер, тело справки собирается из локальных карточек,
модель не имеет права поставить диагноз. Ollama даёт локальный инференс,
Docker изолирует exec, Prometheus и JSON-логи показывают ход, evals фиксируют
выбор gemma2:2b на этом железе.

Разделение ролей позволяет отдельно менять душу критика и карточки жар/кашель
без переписывания графа. Hybrid-политика держит 2B на маршруте. HCM заменяет
«просто RAG». Ошибки демо ("{}" и дамп INDEX) закрыты явно — это часть
честного отчёта, как уточнение времени в эталонном Code Review Report.

Бэклог ICE и три спринта задают порядок: ядро → продукт MedInfo → качество
отчёта и этот документ. Демо на жаре/кашле и боли в груди показывает две
разные ветки справочника: спокойная ОРВИ-подобная справка и порог 103.

Повторная проверка 2026-09-19: 19 unit-тестов зелёные, /health ok,
человеческий отчёт по теме fever_cough собирается без INDEX и abdominal.

30. Приложения (таблицы-шпаргалки к защите)
--------------------------------------------------------------------------------

Почему не vLLM?     Нет GPU-сервера, есть M2/8ГБ.
Почему не 7B?       Несколько вызовов графа, своп врёт бенчу.
Почему LangGraph?   Нужен рисуемый цикл критики.
Почему не VM?       Изолируем exec.
Почему не RAG?      Нет записи, времени, владельца; путает душу с чанками.
Как 2B не врёт?     Карточки + guard + hybrid + critic.
Что за продукт?     Справка по симптомам, не диагноз.
