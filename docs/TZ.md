# Техническое задание — Agentse

## 1. Назначение

Создать **локальную мультиагентную систему**, которая:

1. Работает на личном железе студента (здесь: Apple M2, 8 ГБ) без обязательных облачных LLM.
2. Решает инженерные и мета-задачи (объяснение решений системы, расчёты, безопасный код).
3. Имеет идентичность, память, инструменты, скиллы, оценки и наблюдаемость — не «чат с одной моделью».

Основание: методичка «LLM for Agent» (движок → сравнение лёгких LLM → агент) плюс расширенные требования курса (ТЗ, изоляция, фреймворк, C4/Sequence, soul-файлы, память ≠ RAG, evals, observability).

## 2. Пользователь и сценарии

**Пользователь:** оператор системы (студент / инженер), один канал — web UI или CLI.

**Сценарии:**

- US1. Поставить задачу на естественном языке и получить ответ команды агентов с маршрутом и вердиктом критика.
- US2. Сравнить ≥3 локальные LLM по агентным метрикам и зафиксировать выбор модели.
- US3. Записать/найти факт в иерархической памяти без «засовывания всего корпуса в контекст».
- US4. Исполнить код только в песочнице.
- US5. Прогнать eval suite и увидеть метрики/алерты.

Вне скоупа v1: мультипользовательский SaaS, произвольный интернет-поиск, fine-tune, робототехника.

## 3. Функциональные требования

| ID | Требование | Критерий приёмки |
|---|---|---|
| F1 | Оркестратор + ≥4 специалиста | В трейсе есть planner, researcher, builder, critic |
| F2 | Системные промпты и soul-файлы | `workspace/*.md` инжектятся при старте |
| F3 | Скиллы как файлы | `skills/*/SKILL.md` загружаются `skill_load` |
| F4 | Инструменты | память, граф, workspace, sandbox, calculate |
| F5 | Память многослойная | identity + episodic + graph + curator; RAG не единственный слой |
| F6 | Изоляция исполнения | sandbox без import/сети; Docker-профиль |
| F7 | Evals LLM | JSON, instruction, faithfulness, safety, latency |
| F8 | Evals системы | TSR, handoff, loops, tool errors, critic score |
| F9 | Observability | метрики + JSON-логи + трейсы + алерты |
| F10 | Локальная OSS LLM | Ollama, три модели прогнаны на железе |

## 4. Нефункциональные

- **Железо:** 8 ГБ unified memory → модели 1B–2B, контекст короткий, `num_predict` ограничен.
- **Латентность:** одна задача < 3 мин на дефолтной модели в hybrid-режиме.
- **Безопасность:** workspace jail, запрет перезаписи SOUL/IDENTITY инструментами, sandbox denylist.
- **Наблюдаемость:** `/metrics` всегда; Langfuse/Tempo — опциональные профили Compose.
- **Воспроизводимость:** eval пишет JSON в `data/eval-runs/`.

## 5. Ограничения

- Нет гарантии качества уровня GPT-4: маленькая модель + политика.
- Нет скрытого облачного фолбэка.
- Сеть для агента по умолчанию выключена (кроме Ollama localhost).

## 6. Критерии готовности к защите

1. Репозиторий запускается локально.
2. Есть отчёт с сравнением движков, моделей, фреймворков, изоляции, памяти, evals, observability.
3. Есть C4 и Sequence.
4. Можно устно защитить, почему RAG отвергнут и почему Docker+sandbox, а не «просто VM».
