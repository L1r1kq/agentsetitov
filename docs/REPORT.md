# Отчёт: мультиагентная система Agentse

Преподаватель передал привет и пожелание успехов — этот документ для устной защиты.

## 1. Что сделано

Agentse — локальная система из шести ролей (supervisor, planner, researcher, builder, critic, curator) на **открытой LLM в Ollama**, с soul-файлами в духе OpenClaw, файловыми скиллами, инструментами, иерархической памятью, evals и стеком наблюдаемости.

Железо, на котором принимались решения: **Apple M2, 8 ГБ unified memory**. Это жёсткое ограничение, не сноска.

Официальная методичка (`LLM_for Agent.docx`): (1) сравнить движки локального инференса, (2) развернуть несколько лёгких LLM и сравнить интеллект / галлюцинации / агентность, (3) собрать агента. Ниже закрыты и расширенные пункты курса.

## 2. Движок инференса

Сравнивали то, чем реально поднимают локальные OSS-модели.

| Движок | Сильные стороны | Слабые | Релевантность здесь |
|---|---|---|---|
| **Ollama** | Модельный UX, OpenAI- и native API, Docker-образ, смена модели одной командой | Меньше крутилок батчинга, overhead против голого llama.cpp | **Выбран** |
| llama.cpp / llama-server | Максимум контроля GGUF, минимум слоёв | Самим таскать кванты, API, прогрев, мультимодель | запасной низкоуровневый бэкенд Ollama |
| vLLM | Прод-throughput, PagedAttention, continuous batching | Нужна нормальная GPU-ферма; на M2/8GB бессмысленен | отвергнут |
| MLX | Натив для Apple Silicon | Меньше зоопарка агентных обвязок, другой экосистемный центр | запас на будущее, не оркестрационный стандарт |
| LM Studio / kobold | UI для людей | Плохой контракт для CI/агента | отвергнут |

**Выбор: Ollama.** На учебной машине важнее воспроизводимость и `ollama pull`, чем ещё 8% токенов/с. Под капотом всё равно llama.cpp-стек — мы не притворяемся, что изобрели рантайм. vLLM защищать на 8 ГБ нельзя честно.

## 3. Какие LLM пробовали и почему победитель

Принцип отбора кандидатов (не «какие красивые названия»):

1. Влезают в 8 ГБ вместе с ОС и Python (1B–2B, Q4/Q5).
2. Есть instruct-чат, не base.
3. Разные семьи — чтобы не сравнивать три клона Llama.
4. Агентные критерии важнее викторины: JSON-маршрут, следование инструкции, верность короткому контексту (антигаллюцинация), отказ ломать песочницу, латентность.

Прогнанные локально в Ollama:

| Модель | Размер на диске | Семья | Зачем взяли |
|---|---|---|---|
| `llama3.2:1b` | 1.3 ГБ | Meta | уже стояла; нижняя граница «вообще живой чат» |
| `qwen2.5:1.5b` | 0.99 ГБ | Alibaba | мультиязычность, часто лучший JSON у маленьких Qwen |
| `gemma2:2b` | 1.6 ГБ | Google | другая школа alignment, больше параметров при том же классе железа |

7B не брали в основной стенд: на 8 ГБ это лотерея свопа, агентный граф делает несколько вызовов подряд — своп убивает и качество, и честную латентность.

Протокол: `python3 -m agentse eval-llm`. Веса метрик: tool/json 0.35, faithfulness 0.25, instruction 0.20, safety 0.15, latency 0.05. Цифры последнего прогона — `data/eval-runs/llm-latest.json` и таблица в §3.1 после бенча.

### 3.1 Фактический прогон 2026-09-19 (эта машина)

`python3 -m agentse eval-llm` → `data/eval-runs/llm-20260919T170631Z.json`

| model | tool_json | instruction | faithfulness | safety | latency | total |
|---|---:|---:|---:|---:|---:|---:|
| **gemma2:2b** | **1.00** | 0.67 | **1.00** | 0.00 | **2.25s** | **0.78** |
| qwen2.5:1.5b | 0.60 | **1.00** | 0.50 | **1.00** | 3.00s | 0.73 |
| llama3.2:1b | 0.00 | 0.33 | 0.00 | 0.00 | 4.59s | 0.11 |

Наблюдения, которые надо уметь сказать вслух:

- `llama3.2:1b` на этом железе **не маршрутизатор**: JSON-контракт провален, контекст не держит. Для агента это дисквалификация, даже если чат «милый».
- `qwen2.5:1.5b` лучше слушается формата инструкции и **единственный сдал safety** (`allowed: false`). Хуже держит «ответь из контекста».
- `gemma2:2b` выиграл за **JSON-маршрут и антигаллюцинацию** — ровно те оси, которые ломают граф. Safety он провалил (`{"allowed": true}` на просьбу вывести env) — поэтому песочница и AST-guard не «паранойя», а компенсация модели.
- Дефолт сменён на **`gemma2:2b` по цифрам, не по моде**. Если нужен более послушный отказ от опасного кода — можно переключить на Qwen, сознательно потеряв JSON.

Недостатки победителя: 2B всё ещё короткий горизонт; safety 0; «ровно три слова» не выполнил. Hybrid-политика и critic остаются обязательными.

## 4. Фреймворк

Рассматривали:

| Фреймворк | Плюс | Минус | Вердикт |
|---|---|---|---|
| **LangGraph** | Явный граф, циклы, state, легко рисуется в Sequence | Версии API живые | **Выбран** (сам StateGraph, не чёрный `create_supervisor`) |
| CrewAI | Быстрые роли | Слабее контроль циклов и политик | не наш случай |
| AutoGen | Диалоги агентов | Легко сваливается в болтовню | плохо для 1.5B |
| LlamaIndex | Силён в индексах | Тянет в RAG-центр | конфликт с анти-RAG тезисом |
| Smolagents / PydanticAI | Свежие, тонкие | Меньше учебного следа в C4 | запас |
| Без фреймворка | Полный контроль | Сами писать retry/state/vis | отвергнуто: граф — учебный артефакт |

Почему не «без фреймворка»: курс просит архитектуру и диаграммы. LangGraph *и есть* исполняемая диаграмма. Почему не CrewAI: на защите нельзя честно показать, кто кому handoff-ит, если это спрятано в «команде». Почему не только LangChain agents: ReAct с десятком тулов на 1.5B разваливается; узкие роли + 1–3 тула живут.

## 5. Изоляция: все варианты и связка

| Вариант | Что даёт | Цена | Для Agentse |
|---|---|---|---|
| Процесс / venv | Ничего | нулевая | недостаточно |
| Контейнер приложения | Воспроизводимый runtime | Docker | **да, control plane** |
| Отдельный sandbox-контейнер | Другой user, cap_drop, no-net, mem/pids, read-only | сложнее compose | **да, data plane кода** |
| Docker socket в приложении | Удобный docker run | побег в Docker API = побег на хост | нет |
| gVisor / Kata | Системные вызовы не хостовые | сложный setup на Mac | желательно в проде Linux |
| Firecracker microVM | Жёсткая граница | тяжёлый для ноутбука | overkill v1 |
| Полная VM | Сильная изоляция всего | медленный цикл разработки | не для ежедневной учёбы |
| WASM (wasmtime) | Отличный untrusted compute | бедный Python DX | кандидат v2 для calc |
| nsjail / bubblewrap | Хорошо на Linux | нет на Darwin | серверный профиль |
| macOS sandbox-exec | Локально | не переносится в Linux CI | только fallback |

**Связка: Docker Compose (app + ollama + sandbox) + seccomp-подобные флаги sandbox (`cap_drop ALL`, `no-new-privileges`, `read_only`, `tmpfs`, `pids_limit`, `mem_limit`, `internal` сеть) + статический AST-guard в приложении + local-restricted fallback, если sandbox не поднят.**

Почему не «одна большая VM»: изоляция *кода* важнее изоляции *чата*. VM защищает всё одинаково дорого и мешает eval-циклу. Почему не gVisor на M2: оркестратор Docker Desktop не даёт честный gVisor как на Linux. Почему не WASM сразу: скилл builder — учебный Python, не мини-язык.

Устная формула: *«мы изолируем то, что опасно (exec), а не наказываем UX чата гипервизором»*.

## 6. Архитектура

Иерархия с циклом критики, не «все пишут в общий чат».

- Supervisor не решает предмет.
- Planner не отвечает пользователю.
- Researcher не выдумывает веб.
- Builder без sandbox не считает сложное.
- Critic — единственный источник approve.
- Curator пишет память, не прозу.

C4: [architecture/c4.md](architecture/c4.md). Потоки: [architecture/sequences.md](architecture/sequences.md).

Hybrid routing защищает маленькую модель: LLM может выбрать researcher раньше, но не FINISH без критика. Это осознанный архитектурный костыль и его надо уметь защитить: на 1.5B чистый tool-calling supervisor — лотерея.

## 7. Системные промпты, soul, скиллы, tools

Как у OpenClaw, идентичность — файлы, не fine-tune:

- `workspace/SOUL.md` — ценности и границы.
- `IDENTITY.md` — внешнее имя.
- `AGENTS.md` — устав.
- `USER.md` — директивы о человеке.
- `TOOLS.md` — что существует.
- `MEMORY.md` — кураторские факты.
- `HEARTBEAT.md` / `BOOTSTRAP.md` — пульс и пробуждение.
- `workspace/agents/<role>/SOUL.md` — частные души.

Скиллы — настоящие `SKILL.md`: planning, research, critique, sandbox-code, memory-curation, eval-design.

Tools: `memory_search/write/get`, `graph_neighbors`, `skill_load`, `workspace_read/write` (без SOUL/IDENTITY), `sandbox_exec`, `calculate`. Веба в дефолте нет: на 8 ГБ и в учебной изоляции внешний текст — вектор в душу (см. атаки на SOUL.md).

## 8. Память: почему RAG не оптимален

Vanilla RAG = нарезать корпус, эмбеддинги, top-k, запихнуть в промпт. Для *агента* это плохой единственный слой.

Почему ломается:

1. **Нет записи.** Агент не становится умнее после решения, если некуда писать.
2. **Сходство ≠ уместность.** «Похожий чанк» про RAG не отвечает на «какой движок выбрали вчера».
3. **Нет времени.** Факт 2024 и 2026 лежат рядом.
4. **Нет противоречий.** Два куска с разными дефолтами модели.
5. **Нет разделения identity / episode / procedure.** SOUL не должен конкурировать в ANN с daily note.
6. **Мультиагентность.** Кто владеет фактом? RAG притворяется, что никто.
7. **Маленький контекст 1.5B.** Top-k=8 убивает окно; нужна селекция слоями.

Что смотрели вместо «просто RAG»:

| Подход | Суть | Недостаток | Почему не единственный |
|---|---|---|---|
| LlamaIndex / naive RAG | быстро | см. выше | отвергнут как центр |
| GraphRAG (Microsoft) | сообщества и отчёты | дорогой batch, тяжёлый для 8 ГБ | идеи графа взяли, движок нет |
| HippoRAG / LightRAG | multi-hop ближе к памяти человека | исследовательский DX | слишком много движущихся частей |
| MemGPT / Letta | OS-paging контекста | свой рантайм, облачный крен | идея curator/sleep взята |
| Mem0 | слой памяти как продукт | внешний сервис | зависимость |
| Zep / Graphiti | темпоральный граф | ops | идея рёбер + времени взята |
| OpenClaw markdown | прозрачная душа | нет графа и decay | файлы взяли как identity |

**Наш выбор: Hierarchical Cognitive Memory (HCM).**

- Identity markdown — всегда в бутстрапе, с бюджетом символов.
- Episodic SQLite + daily `memory/YYYY-MM-DD.md` + FTS5.
- Semantic graph: entities/relations + strength + decay.
- Curator после задачи (аналог sleep/dream).
- Поиск гибридный: lexical + graph + recency, не косинус как религия. Эмбеддинги опциональны (`nomic-embed-text`), не обязательны: на 8 ГБ второй модели может не быть.

Недостатки HCM: сами пишем консолидацию; curator на 1.5B может записать шум; нет полноценного temporal KG; lexical слаб на синонимах. Это честно лучше, чем делать вид, что RAG решает агентную память.

Что улучшить: HippoRAG-подобные Personalized PageRank по нашему графу; LLM-judge на записи фактов; эмбеддинги только для daily notes, не для SOUL; read-only SOUL в git + drift alert (как soul-guardian).

## 9. Evals (не скип)

### 9.1 Как оценивать LLM (не агента)

Бесполезно тащить полный MMLU на 1.5B и заявлять «интеллект». Для агентности:

| Метрика | Что ловим | Среда |
|---|---|---|
| tool_json | валидный маршрут | Ollama localhost, suite `eval-llm` |
| instruction | ровно N слов, язык | то же |
| faithfulness | ответ из контекста / НЕИЗВЕСТНО | то же |
| safety | отказ exec/os | то же |
| latency | живость на 8 ГБ | histogram |

LLM-as-judge на этой машине — сам маленькая модель, поэтому судья **детерминированный** (парсеры, словари). Это недостаток (не оцениваем тонкий стиль) и достоинство (нет картеля двух Qwen).

### 9.2 Как оценивать agentic system

| Метрика | Смысл |
|---|---|
| Task Success Rate | золотой ответ/маркер в финале |
| Handoff accuracy | нужные узлы были в route_trace |
| Loop rate | упёрлись в max_steps |
| Tool error rate | sandbox fail |
| Critic score | самооценка критика + можно сверка с автоматикой |
| Avg steps / e2e latency | стоимость |
| Memory write/recall | отдельный кейс «как зовут систему» |

Среда прогона: тот же процесс, реальный граф, реальная Ollama. Не мок «как будто агент». Непрерывность: `scripts/nightly_eval.sh` → JSON → `agentse_eval_score` → алерт `AgentseEvalDrop`.

### 9.3 Фактический agent bench 2026-09-19 (`gemma2:2b`)

| metric | value |
|---|---|
| task_success_rate | 0.67 (2/3) |
| handoff_accuracy | **1.00** |
| avg_critic_score | 0.80 |
| loop_rate | **0.00** |
| tool_error_rate | **0.00** |
| avg_steps | 6 |

Кейс `calc_area` закрыт числом 28. Кейс `identity_name` назвал Agentse. Кейс `memory_why_not_rag` провален по лексическим маркерам: модель объяснила «RAG упрощает», но не сказала «граф / слой / консолидация». Это честный долг 2B, не приукрашенный TSR. Handoff при этом идеальный — архитектура жива, генерация ещё нет.

Специфика агентного перфа vs обычного сервиса: мало RPS, много **петель**, **токен×шаг**, **ложных FINISH**, **дрейфа промпта/души**. p95 latency без loop_rate — слепой мониторинг.

## 10. Observability

Сравнивали стеки:

| Стек | Даёт | Не даёт | Вердикт |
|---|---|---|---|
| LangSmith | лучший DX LangChain | облако, деньги, учебная зависимость | не центр |
| **Langfuse** | локальные traces/generations/scores | отдельная Postgres, профиль compose | **опциональный LLM-native** |
| Langtrace | OTEL-крен | меньше экосистемы | запас |
| Phoenix (Arize) | один контейнер | меньше «продуктового» alerting | запас |
| **Prom + Grafana + Alertmanager** | метрики и алерты как у обычного сервиса | нет семантики промпта | **обязательный infra** |
| **OTEL → Tempo + JSONL файлы** | разбор одного трейса без SaaS | сами крутить | **обязательный минимум** |
| Loki | центральные логи | ещё одна JVM/память на 8 ГБ | отложен |

**Связка: всегда метрики+JSON-логи+file traces; OTEL/Tempo и Grafana — профиль `obs`; Langfuse — профиль `langfuse`, когда есть RAM.**

Что мониторим: `agentse_tasks_*`, latency, LLM tokens/errors, handoffs, loop_guard, sandbox_denies, critic_verdicts, memory writes/hits, eval gauges.

Что ещё модно и полезно: token cost per successful task, prompt-injection denials, soul-file checksum drift, queue time Ollama, critic-auto disagreement.

Специфика агента: трейс — это **граф ролей**, не один HTTP span. Алертить надо петли и падение TSR, не только 5xx.

## 11. Как защищать устно (шпаргалка)

1. «Почему не vLLM?» — нет GPU-сервера, есть M2/8GB.
2. «Почему не 7B?» — несколько вызовов графа, своп врёт бенчу.
3. «Почему LangGraph, а не Crew?» — нужен рисуемый цикл критики.
4. «Почему не VM?» — изолируем exec, не мучаем DX.
5. «Почему не RAG?» — нет записи, времени, владельца факта, путает душу с чанками.
6. «Как не врёт 1.5B?» — hybrid policy, critic, JSON-контракт, evals каждую ночь.
